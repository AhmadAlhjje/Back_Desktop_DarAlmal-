==================================================
SEQUELIZE REQUIREMENTS
==================================================

Use Sequelize ORM.

Do not use raw SQL as the normal data access mechanism.

All standard database access MUST happen through Sequelize models
inside Infrastructure repositories.

Raw SQL is allowed ONLY if:

1. Sequelize cannot reasonably implement the required query.
2. There is a proven performance reason.
3. It exists only in Infrastructure.
4. It uses bound replacements.
5. It is documented.
6. It does not leak into Application or Domain.

Never place Sequelize queries inside:

Controllers
Routes
Domain entities
Use Cases

Sequelize Models are persistence models.

They are NOT Domain Entities.

Do not treat:

ClientModel

as:

Client Domain Entity.

Use Mappers.

Flow:

Sequelize Model
↓
Mapper
↓
Domain Entity

and:

Domain Entity
↓
Mapper
↓
Persistence Data

==================================================
SEQUELIZE MIGRATIONS
==================================================

Use migrations for schema changes.

Never use:

sequelize.sync({ force: true })

in production.

Never use:

sequelize.sync({ alter: true })

as the production migration strategy.

Database schema evolution MUST happen through migrations.

Development may use sync only in isolated tests if justified.

==================================================
UNIT OF WORK
==================================================

Financial operations MUST use Sequelize transactions.

Do not expose Sequelize Transaction type to Application.

Create Application Port:

UnitOfWork

Infrastructure implementation:

SequelizeUnitOfWork

Concept:

unitOfWork.execute(async repositories => {

    const movement =
        await repositories.movementRepository.create(...)

    await repositories.transferRepository.create(...)

    await repositories.journalRepository.createMany(...)

})

Implementation internally:

sequelize.transaction(async transaction => {

    create transaction-bound repositories

    run callback

})

All repositories inside the callback MUST use the SAME transaction.

Do NOT accidentally use the global repository instance during the
financial transaction.

==================================================
NO TRANSACTION IN CONTROLLERS
==================================================

Forbidden:

controller:

const transaction =
    await sequelize.transaction()

This is NOT allowed.

Transactions belong to Infrastructure UnitOfWork and are orchestrated
from Application Use Cases.

==================================================
FINANCIAL MONEY RULE
==================================================

Never calculate money using normal JavaScript floating-point Number.

Use:

decimal.js

For example:

new Decimal("1000.25")

Database:

DECIMAL

Sequelize may return DECIMAL values as strings.

Preserve that precision.

Never convert DECIMAL financial values to Number just for convenience.
